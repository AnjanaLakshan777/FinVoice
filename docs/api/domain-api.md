# Domain API (v1)

The FinVoice backend API for users, financial profiles, financial goals, financial calculations and financial-literacy knowledge. Clients are the web app, the voice gateway and future phone/AI flows.

**The API is authoritative.** Every rule below is enforced by the backend (request validation, then service checks, then database constraints), whatever a client, voice flow or AI model has already checked. Clients may propose values; the API decides what is stored.

> **No authentication yet.** Any caller that can reach the API can read and change any user. Do not expose the API publicly until authentication and authorisation are in place (a later step).

## Basics

| Item       | Value                                                                                                       |
| ---------- | ----------------------------------------------------------------------------------------------------------- |
| Base path  | `/api/v1` (the health checks `GET /health` and `GET /health/ready` stay at the root)                        |
| Local URL  | `http://127.0.0.1:4000/api/v1` (`API_HOST`/`API_PORT`)                                                      |
| Format     | JSON request and response bodies; send `Content-Type: application/json`                                     |
| IDs        | UUIDs generated by the database (UUIDv7). Clients never send ids, timestamps or other server-managed fields |
| Timestamps | `createdAt` / `updatedAt`: ISO 8601 in UTC, e.g. `"2026-09-26T06:34:09.349Z"`                               |
| Contracts  | Request schemas (zod) and response types are in [`packages/contracts`](../../packages/contracts)            |

## Endpoints

| Method  | Path                               | Success | Purpose                                     |
| ------- | ---------------------------------- | ------- | ------------------------------------------- |
| `POST`  | `/users`                           | 201     | Create a user                               |
| `GET`   | `/users/:userId`                   | 200     | Get a user                                  |
| `PATCH` | `/users/:userId`                   | 200     | Update a user                               |
| `GET`   | `/users/:userId/financial-profile` | 200     | Get the user's financial profile            |
| `PUT`   | `/users/:userId/financial-profile` | 200     | Create or replace the user's profile        |
| `POST`  | `/users/:userId/goals`             | 201     | Create a goal                               |
| `GET`   | `/users/:userId/goals`             | 200     | List the user's goals (filters, pagination) |
| `GET`   | `/users/:userId/goals/:goalId`     | 200     | Get one of the user's goals                 |
| `PATCH` | `/users/:userId/goals/:goalId`     | 200     | Update one of the user's goals              |
| `POST`  | `/calculations/loan`               | 200     | Calculate a loan repayment                  |
| `POST`  | `/calculations/savings`            | 200     | Calculate a savings plan                    |
| `POST`  | `/calculations/budget`             | 200     | Calculate a budget summary                  |
| `GET`   | `/knowledge/categories`            | 200     | Categories that have published knowledge    |
| `GET`   | `/knowledge/articles`              | 200     | List or search published knowledge articles |
| `GET`   | `/knowledge/articles/:slug`        | 200     | Get one published knowledge article         |

There are no delete endpoints and no list-users endpoint. Goals end through their `status` (`COMPLETED`, `CANCELLED`). Users are deactivated through `status: "INACTIVE"`.

## Request rules that apply everywhere

- **Unknown properties are rejected** (400), never silently ignored. For example, `isAdmin`, `password`, `id`, `createdAt` or `status` on creation.
- **Path ids must be UUIDs**. Anything else gets 400 before any lookup.
- **Strings are trimmed** where noted. Blank display names become `null`; blank goal names are rejected.
- **PATCH bodies** must contain at least one field. Fields that are not sent are left unchanged, and `null` clears a nullable field.

## Money

Amounts are **decimal strings**, never JSON numbers. JSON numbers are binary floating point, which cannot represent most decimal fractions exactly (`0.1 + 0.2 !== 0.3`).

| Rule            | Detail                                                                                                             |
| --------------- | ------------------------------------------------------------------------------------------------------------------ |
| Request format  | `^(0\|[1-9][0-9]{0,11})(\.[0-9]{1,2})?$`: up to 12 integer digits, up to 2 decimal places                          |
| Accepted        | `"100"`, `"100.5"`, `"100.50"`, `"0"`, `"999999999999.99"`                                                         |
| Rejected        | `"100.123"`, `"1.999"`, `"-10.00"`, `"abc"`, `"NaN"`, `"Infinity"`, `"1e5"`, `"007"`, `" 100"`, `100.5` (a number) |
| Response format | Always exactly 2 decimal places: `"100"` is returned as `"100.00"`                                                 |
| Currency        | ISO 4217 code, 3 uppercase letters (`"LKR"`). Defaults to `"LKR"` when omitted                                     |

Values with more than 2 decimal places are rejected, not rounded. The server compares and stores amounts with exact decimal arithmetic (`NUMERIC(14,2)` in PostgreSQL).

## Calendar dates

`targetDate` is a calendar date `"YYYY-MM-DD"`, not a timestamp. It is stored as a PostgreSQL `DATE` and returned exactly as sent, so time zones never shift it. Impossible dates such as `"2027-02-30"` are rejected, not rolled over. Timestamps are not accepted.

## Users

### `POST /users`

```json
{ "phoneNumber": "+94771234567", "preferredLanguage": "SI", "displayName": "Kamal" }
```

| Field               | Rules                                                                                      |
| ------------------- | ------------------------------------------------------------------------------------------ |
| `phoneNumber`       | Required. E.164: `+`, then 8–15 digits, first digit not 0, no spaces. Must be unique (409) |
| `preferredLanguage` | Required. `SI`, `TA` or `EN`                                                               |
| `displayName`       | Optional string or null, trimmed, at most 100 characters. Blank means `null`               |

New users are `ACTIVE`, with time zone `Asia/Colombo`. `201 Created`:

```json
{
  "id": "01a0dc6b-d44b-7875-ae8a-3f65af5078e0",
  "phoneNumber": "+94771234567",
  "displayName": "Kamal",
  "preferredLanguage": "SI",
  "timezone": "Asia/Colombo",
  "status": "ACTIVE",
  "createdAt": "2026-09-26T06:34:09.349Z",
  "updatedAt": "2026-09-26T06:34:09.349Z"
}
```

### `GET /users/:userId`

Returns the user (`200`), `404` if it does not exist, or `400` for a malformed id.

### `PATCH /users/:userId`

Any of `phoneNumber`, `preferredLanguage`, `displayName` (null clears it) and `status` (`ACTIVE`, `INACTIVE`), with the same rules as creation. `id`, `timezone`, `createdAt` and `updatedAt` cannot be changed. A phone number that belongs to another user returns `409`.

## Financial profile

A user has at most one financial profile.

### `PUT /users/:userId/financial-profile`

Creates the profile, or **replaces it entirely**. Fields that are omitted are reset: amounts become `null` ("not provided yet") and the currency becomes `LKR`. Send every value you want to keep.

```json
{ "monthlyIncome": "150000.00", "monthlyExpenses": "100000.00", "currency": "LKR" }
```

| Field             | Rules                                       |
| ----------------- | ------------------------------------------- |
| `monthlyIncome`   | Optional non-negative money string, or null |
| `monthlyExpenses` | Optional non-negative money string, or null |
| `currency`        | Optional ISO 4217 code, default `LKR`       |

`200 OK` (whether the profile was created or replaced):

```json
{
  "userId": "01a0dc6b-d44b-7875-ae8a-3f65af5078e0",
  "monthlyIncome": "150000.00",
  "monthlyExpenses": "100000.00",
  "currency": "LKR",
  "createdAt": "2026-09-26T06:34:09.904Z",
  "updatedAt": "2026-09-26T06:34:09.904Z"
}
```

`404` if the user does not exist. No profile is created for an unknown user.

### `GET /users/:userId/financial-profile`

`200` with the profile. `404` with message `"User not found"` or `"Financial profile not found"`.

## Financial goals

A goal always belongs to one user. Every goal endpoint is scoped to `/users/:userId`: a goal that belongs to a different user is answered with the same `404` as a goal that does not exist, so its existence is not revealed.

### `POST /users/:userId/goals`

```json
{
  "type": "SAVINGS",
  "name": "Emergency Fund",
  "targetAmount": "300000.00",
  "currentAmount": "50000.00",
  "targetDate": "2027-06-30",
  "currency": "LKR"
}
```

| Field           | Rules                                                                |
| --------------- | -------------------------------------------------------------------- |
| `type`          | Required. `SAVINGS`, `EMERGENCY_FUND`, `DEBT_REPAYMENT` or `OTHER`   |
| `name`          | Required, trimmed, 1–120 characters                                  |
| `targetAmount`  | Required money string, greater than 0                                |
| `currentAmount` | Optional money string, default `"0"`; must not exceed `targetAmount` |
| `targetDate`    | Optional `"YYYY-MM-DD"` or null                                      |
| `currency`      | Optional ISO 4217 code, default `LKR`                                |

`status` cannot be sent on creation (new goals are `ACTIVE`). `201 Created`:

```json
{
  "id": "01a0dc6b-d7c0-7e7d-9d3e-087a7d65c635",
  "userId": "01a0dc6b-d44b-7875-ae8a-3f65af5078e0",
  "type": "SAVINGS",
  "name": "Emergency Fund",
  "targetAmount": "300000.00",
  "currentAmount": "50000.00",
  "currency": "LKR",
  "targetDate": "2027-06-30",
  "status": "ACTIVE",
  "createdAt": "2026-09-26T06:34:10.235Z",
  "updatedAt": "2026-09-26T06:34:10.235Z"
}
```

### `GET /users/:userId/goals`

Query parameters, all optional:

| Parameter | Values                                                 | Default |
| --------- | ------------------------------------------------------ | ------- |
| `status`  | `ACTIVE`, `COMPLETED`, `CANCELLED`                     | all     |
| `type`    | `SAVINGS`, `EMERGENCY_FUND`, `DEBT_REPAYMENT`, `OTHER` | all     |
| `page`    | integer ≥ 1                                            | `1`     |
| `limit`   | integer 1–100                                          | `20`    |

Other parameters are rejected (400). Results are ordered newest first (`createdAt` descending, then `id`). A page past the end returns an empty `data` array.

```json
{
  "data": [{ "id": "…", "name": "Emergency Fund", "status": "ACTIVE", "…": "…" }],
  "meta": { "page": 1, "limit": 20, "total": 1, "totalPages": 1 }
}
```

### `GET /users/:userId/goals/:goalId`

`200` with the goal, or `404` (`"User not found"` / `"Financial goal not found"`).

### `PATCH /users/:userId/goals/:goalId`

Any of `type`, `name`, `targetAmount`, `currentAmount`, `targetDate` (null clears it), `status` and `currency`, with the same rules as creation. The rules are checked again against the goal **as it would be after the update**:

- stored `currentAmount` 100000, patch `{"targetAmount": "80000"}`: rejected;
- stored `targetAmount` 300000, patch `{"currentAmount": "400000"}`: rejected.

The status changes only when the client sends `status`. Reaching the target does not complete a goal automatically. Any status can be set from any other.

## Calculations

Stateless calculations by the [financial calculation engine](../architecture/financial-calculation-engine.md). They read and store nothing (no user is needed), always return `200` on success, and give the same result for the same input.

- **Send inputs only.** Result fields such as `monthlyPayment`, `finalPayment`, `totalInterest`, `totalRepayment`, `requiredMonthlyContribution`, `monthlySurplus`, `savingsRate` or `calculationVersion` are rejected with `400` as unknown properties. The server always calculates them itself.
- **Money** follows the [money rules](#money). **Percentages** are decimal strings with at most 2 decimal places (`"12"`, `"12.50"`). Months are JSON integers.
- **Outputs**: money and percentages are strings with exactly 2 decimal places, rounded half away from zero. Inputs are echoed back normalised (`"500000"` → `"500000.00"`) but never rounded; invalid values are rejected.
- Every result includes `"calculationVersion": "1"`, which identifies the rules used.
- Results are **illustrative arithmetic, not financial advice or a lender quote**.

### `POST /calculations/loan`

Standard reducing-balance loan with equal monthly payments.

| Field                | Rules                                 |
| -------------------- | ------------------------------------- |
| `principal`          | Required money string > 0             |
| `annualInterestRate` | Required percentage string, 0–1000.00 |
| `termMonths`         | Required whole number, 1–600          |

```json
{ "principal": "500000.00", "annualInterestRate": "12.00", "termMonths": 36 }
```

`200 OK`:

```json
{
  "calculationVersion": "1",
  "principal": "500000.00",
  "annualInterestRate": "12.00",
  "termMonths": 36,
  "monthlyPayment": "16607.15",
  "finalPayment": "16607.33",
  "totalRepayment": "597857.58",
  "totalInterest": "97857.58",
  "assumptions": {
    "interestMethod": "reducing_balance",
    "paymentFrequency": "monthly",
    "monthlyRateMethod": "annual_rate_divided_by_12",
    "feesIncluded": false,
    "insuranceIncluded": false,
    "earlyRepaymentIncluded": false
  }
}
```

- `monthlyPayment` is the regular payment for months 1 to `termMonths` − 1: the exact payment rounded to cents.
- `finalPayment` is the last payment. It absorbs the cent rounding, so it can differ from `monthlyPayment` by a few cents.
- `totalRepayment` is the exact payment × `termMonths`, rounded once, and always equals `monthlyPayment` × (`termMonths` − 1) + `finalPayment`.
- `totalInterest` = `totalRepayment` − `principal`. It is never negative, and is exactly `"0.00"` for a 0% loan: 100,000 over 12 months is 11 × 8,333.33 plus a final 8,333.37 = 100,000.00.
- For a one-month loan, `monthlyPayment` and `finalPayment` are the same single payment.
- A principal so small that the regular payment would be `0.00` is rejected.

### `POST /calculations/savings`

Monthly contributions to reach a target. No interest, returns or inflation.

| Field           | Rules                                       |
| --------------- | ------------------------------------------- |
| `targetAmount`  | Required money string > 0                   |
| `currentAmount` | Required money string ≥ 0, ≤ `targetAmount` |
| `months`        | Required whole number, 1–600                |

```json
{ "targetAmount": "300000.00", "currentAmount": "50000.00", "months": 12 }
```

`200 OK`:

```json
{
  "calculationVersion": "1",
  "targetAmount": "300000.00",
  "currentAmount": "50000.00",
  "remainingAmount": "250000.00",
  "months": 12,
  "requiredMonthlyContribution": "20833.33",
  "finalContribution": "20833.37",
  "plannedTotalContribution": "250000.00",
  "differenceFromTarget": "0.00"
}
```

- `requiredMonthlyContribution` is the regular contribution for months 1 to `months` − 1, rounded to cents.
- `finalContribution` is the last one. It absorbs the rounding, so the plan reaches the target exactly: `plannedTotalContribution` = `remainingAmount`, and `differenceFromTarget` is `"0.00"`.
- If `currentAmount` equals `targetAmount`, every amount is `"0.00"`.

### `POST /calculations/budget`

| Field             | Rules                     |
| ----------------- | ------------------------- |
| `monthlyIncome`   | Required money string ≥ 0 |
| `monthlyExpenses` | Required money string ≥ 0 |

```json
{ "monthlyIncome": "150000.00", "monthlyExpenses": "100000.00" }
```

`200 OK`:

```json
{
  "calculationVersion": "1",
  "monthlyIncome": "150000.00",
  "monthlyExpenses": "100000.00",
  "monthlySurplus": "50000.00",
  "expenseRatio": "66.67",
  "savingsRate": "33.33",
  "status": "SURPLUS"
}
```

- `monthlySurplus` = income − expenses. It is negative for a deficit.
- `expenseRatio` = expenses / income × 100.
- `savingsRate` = surplus / income × 100, which can be negative.
- `status` is `SURPLUS`, `BREAK_EVEN` or `DEFICIT`.
- With zero income, `expenseRatio` and `savingsRate` are `null`.

## Knowledge

A read-only API over curated, source-backed financial-literacy articles (see [financial-knowledge-base.md](../architecture/financial-knowledge-base.md)).

- Only **published** articles are returned. Drafts and archived articles never appear, and asking for one by slug gives the same `404` as an unknown slug.
- Every article includes its **source** (publisher, title, URL, section, when last verified) and a **review** status.
- There are **no write endpoints**. Content is managed through a controlled seed.
- Articles are educational. They do not recommend products or institutions, and contain no calculations: use the [calculation endpoints](#calculations) for figures.

**Language fallback:** `language` selects `EN` (default), `SI` or `TA`. If an article has no translation in that language, the English text is returned, and the response shows both `requestedLanguage` and the `language` actually returned. Text is never machine-translated on the fly. `translationStatus` shows how the returned text was produced:

- `OFFICIAL`: the source's own wording.
- `HUMAN_REVIEWED`: checked by a qualified person.
- `MACHINE_ASSISTED`: not yet reviewed.

All current content is `MACHINE_ASSISTED`.

**Time-sensitive facts:** `review.reviewRequired` is `true` when an article contains facts that can change (`isTimeSensitive`) and is past its review date. Such articles are still returned, but their figures must not be presented as current; check the source.

### `GET /knowledge/categories`

Categories with at least one published article, in a fixed order:

```json
{
  "data": [
    { "category": "SAVING", "articleCount": 2 },
    { "category": "BUDGETING", "articleCount": 1 }
  ]
}
```

Categories: `SAVING`, `BUDGETING`, `BORROWING`, `DIGITAL_FINANCE`, `CONSUMER_PROTECTION`, `SCAMS`, `DEPOSIT_PROTECTION`, `GENERAL_FINANCIAL_LITERACY`.

### `GET /knowledge/articles`

| Parameter  | Values                                                                                                                 | Default |
| ---------- | ---------------------------------------------------------------------------------------------------------------------- | ------- |
| `language` | `EN`, `SI`, `TA`                                                                                                       | `EN`    |
| `category` | one of the categories above                                                                                            | all     |
| `query`    | 1–100 characters, matched case-insensitively in title, summary, body or keywords, in the requested language or English | none    |
| `page`     | integer ≥ 1                                                                                                            | `1`     |
| `limit`    | integer 1–100                                                                                                          | `20`    |

Unknown parameters are rejected with `400`. Results are ordered by category, then slug. `%` and `_` in `query` are matched literally.

```json
{
  "data": [
    {
      "slug": "deposit-insurance",
      "category": "DEPOSIT_PROTECTION",
      "audience": "GENERAL_PUBLIC",
      "requestedLanguage": "SI",
      "language": "EN",
      "translationStatus": "MACHINE_ASSISTED",
      "title": "Deposit insurance in Sri Lanka",
      "summary": "The Sri Lanka Deposit Insurance Scheme protects deposits up to Rs. 1,100,000 per depositor, per institution, if a member institution fails.",
      "body": "The Sri Lanka Deposit Insurance Scheme (SLDIS) protects depositors …",
      "keywords": [
        "deposit insurance",
        "sldis",
        "deposits",
        "compensation",
        "bank",
        "finance company"
      ],
      "source": {
        "publisher": "Central Bank of Sri Lanka",
        "title": "Sri Lanka Deposit Insurance Scheme",
        "url": "https://www.cbsl.gov.lk/en/sri-lanka-deposit-insurance-scheme",
        "type": "OFFICIAL_REGULATOR",
        "section": "Sri Lanka Deposit Insurance Scheme: coverage and member institutions",
        "lastVerifiedAt": "2026-09-26T08:00:00.000Z"
      },
      "review": {
        "isTimeSensitive": true,
        "reviewRequired": false,
        "lastReviewedAt": "2026-09-26T08:00:00.000Z"
      }
    }
  ],
  "meta": { "page": 1, "limit": 20, "total": 1, "totalPages": 1 }
}
```

The `body` is plain text: paragraphs are separated by blank lines, and list items start with `- `.

### `GET /knowledge/articles/:slug`

Returns one published article in the same shape, for example `GET /knowledge/articles/protect-pin-otp-passwords?language=SI`.

- The only query parameter is `language` (default `EN`).
- A malformed slug (not lower-case kebab-case) returns `400`.
- An unknown, draft or archived slug returns `404` with `"Knowledge article not found"`.

## Errors

Every error from the API (domain routes, unknown routes and malformed requests) has the same shape:

```json
{
  "statusCode": 400,
  "code": "VALIDATION_ERROR",
  "message": "Request validation failed",
  "details": [{ "field": "targetAmount", "message": "Must be greater than 0" }]
}
```

`details` appears on validation errors, and on conflicts where a field is known. `field` is the dotted path of the offending field, or `null` when the problem is the request as a whole (for example an unknown property).

| Status | `code`                | When                                                                                                         |
| ------ | --------------------- | ------------------------------------------------------------------------------------------------------------ |
| 400    | `VALIDATION_ERROR`    | Invalid body, query or path id, unknown property, or a broken domain rule (`currentAmount` > `targetAmount`) |
| 400    | `BAD_REQUEST`         | The request could not be parsed (for example malformed JSON)                                                 |
| 404    | `NOT_FOUND`           | The user, profile or goal does not exist or belongs to another user; unknown route                           |
| 409    | `CONFLICT`            | Phone number already registered; the data changed concurrently (retrying may succeed)                        |
| 413    | `PAYLOAD_TOO_LARGE`   | Request body over 100 kB                                                                                     |
| 503    | `SERVICE_UNAVAILABLE` | The database cannot be reached                                                                               |
| 500    | `INTERNAL_ERROR`      | Anything unexpected                                                                                          |

Error responses never contain SQL, database or Prisma messages, constraint names, stack traces, connection strings or credentials. Unexpected errors are logged on the server, with connection strings redacted.

## Example session (curl)

```sh
API=http://127.0.0.1:4000/api/v1

curl -s -X POST $API/users -H 'content-type: application/json' \
  -d '{"phoneNumber":"+94000000901","preferredLanguage":"SI","displayName":"Demo"}'
# → note the "id" and use it below as USER_ID

curl -s -X PUT $API/users/$USER_ID/financial-profile -H 'content-type: application/json' \
  -d '{"monthlyIncome":"150000.00","monthlyExpenses":"100000.00"}'

curl -s -X POST $API/users/$USER_ID/goals -H 'content-type: application/json' \
  -d '{"type":"EMERGENCY_FUND","name":"Emergency Fund","targetAmount":"300000.00","targetDate":"2027-06-30"}'

curl -s "$API/users/$USER_ID/goals?status=ACTIVE&page=1&limit=20"

# Calculations need no stored data
curl -s -X POST $API/calculations/loan -H 'content-type: application/json' \
  -d '{"principal":"500000.00","annualInterestRate":"12.00","termMonths":36}'
```

In PowerShell, use `Invoke-RestMethod`:

```powershell
$api = "http://127.0.0.1:4000/api/v1"
$user = Invoke-RestMethod -Method Post "$api/users" -ContentType "application/json" `
  -Body '{"phoneNumber":"+94000000901","preferredLanguage":"SI"}'
Invoke-RestMethod "$api/users/$($user.id)"
```

`+94 0…` numbers are never assigned in Sri Lanka, so they are safe to use as test data.
